Why hire me

Pick a view

The 30-second fit

  • 8+ years shipping software to consumer scale, now focused on production LLM systems.
  • Shipped, not just prototyped: public RAG and multi-agent demos on AWS, and agent evaluation for an app on Google Play.
  • Numbers, not adjectives: 1.00 Recall@5 and 0.99 faithfulness on held-out data; a model choice that saved ~94% per run.
  • Safety-minded: access control enforced by the database; 0 of 58 unauthorized-access attempts succeeded.
  • Clear communicator: every project documents its decisions, its failures and how they were found.

The technical depth

  • Retrieval: hybrid BM25 + vector search with RRF and a cross-encoder reranker; structure-aware chunking; a relevance gate that refuses before the LLM call.
  • Access control: Postgres row-level security with SET LOCAL ROLE per request, so both indexes filter before ranking; ACL checks after every stage fail closed; role only from a signed JWT.
  • Evaluation: golden sets written before code, sealed held-out sets run once, pre-registered predictions; RAGAS faithfulness plus code-graded Recall@5 / MRR@10, key facts and citations; deterministic agent evals (tool selection, call budgets, confirmation ordering, grounding).
  • Agents: Claude Agent SDK with an in-process MCP server; LangGraph tool loops; schema-validated tools, restricted SQL permissions, human approval.
  • Production: OpenTelemetry traces per stage (Jaeger), Prometheus p95 / tokens / cost, a role-scoped semantic cache, rate limits and spend caps, Docker on AWS.

The forward deployed fit

  • From problem to live system: I took the Copilot from a written plan to a public HTTPS deployment on AWS (Docker Compose, Caddy, firewall, budget alerts), with a deploy runbook anyone can follow.
  • Fits the data and permissions a company already has: access rules are mapped onto Postgres roles and row-level security, so the AI sees only what each user is allowed to see.
  • Agentic platform work: MCP servers, the Claude Agent SDK and LangGraph tool loops, with schema-validated tools, restricted permissions and human approval before actions.
  • Proves value with evidence: success metrics defined up front, then a sealed held-out run; model and provider choices made on measured quality, latency and cost (1/17th the cost at higher accuracy).
  • Adapts to the environment: the same system runs fully local (Ollama, open-source reranker) or on hosted APIs (Voyage, Claude) by switching one profile.
  • Leaves it operable: traces, metrics, rate limits and spend caps in place, plus design notes that record every decision and every failure.

Bug-triage agents

A LangGraph multi-agent system that triages bug reports. A supervisor routes each request, three investigators search the code in parallel (stack trace, described behavior, recent commits), a verifier checks each suspect against the lines it cites, and a person approves every GitHub issue before it's filed. It's scored on AnkiDroid bugs that maintainers already fixed, each investigated against the code from before its report.

87–90% fixed file in top 5 (held-out) Single agent: 85–92% at ~⅓ the cost Hybrid search: 69% 10/10 injection attempts blocked ≈ $0.019 / bug
  • Built a single-agent baseline and measured both: multi-agent tied it at about 3× the cost
  • 39 held-out bugs never used for tuning; each LLM method run twice to show run-to-run variance
  • Agents can only read; filing happens in code, after human approval, to a sandbox repo
  • Report text never reaches the router or the issue writer, closing a prompt-injection path
  • Every tool locked to the code, history and issues from before the report

How I work

Principles

Measure before you build.Metrics, golden questions and predictions are written before the code; held-out sets are sealed and run once.
Enforce permissions in the data, not the prompt.Roles come from signed tokens, and the database decides what a request can see.
Fail closed, refuse quietly.Every stage re-checks access; a refusal never reveals that restricted data exists.
Write down what broke.Each project keeps a log of its failures, how they were found and how they were fixed.
